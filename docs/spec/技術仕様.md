# pcloud-manager 技術仕様

Last updated: 2026-05-06

## 1. 目的

`pcloud-manager` は、この環境の `rclone` / `pCloud` 運用をまとめるための macOS 向け Python CLI です。public entrypoint は zsh wrapper ですが、実装本体は `/Users/takafumi/p-core/dev/pcloud-tools/` の Python package へ移行済みです。

主な責務は次のとおりです。

- `p-core` と `pcloud:core` の `bisync`
- `vault` / `crypt` の optional mount
- `launchd` による autosync の管理
- `launchd` による `pcloud-pushd` / `pcloud-diffd` の human-gated daemon 起動
- `status` / `doctor` による状態可視化
- allowlist ベースの sync scope 制御
- stale lock / missing listing など、運用でよく起きる障害の軽減
- pushd/diffd の queue-only / diffid-only 監視を実 upload/download から分離すること

現在の live 状態:

- `pcloud-pushd` は `com.takafumi.pcloud-pushd` として launchd に loaded/running。operational plist は `fswatch resident-run --execute` と `PCLOUD_TOOLS_PUSHD_FSWATCH_RESIDENT_GATE=operator-approved-fswatch-resident-v1` を含む。検証では allowlist 内一時ファイルから queue append 1 件を確認し、queue/file は cleanup 済み。
- `pcloud-diffd` は `com.takafumi.pcloud-diffd` として launchd に loaded。KeepAlive false の bounded live API one-shot payload が `StartInterval 60` で定期起動している。observed periodic runs は diffid を進め、current plan 外 record を skip し、download records appended 0 を維持している。`diffd launchd resident-plist --start-interval-seconds N` は同じ operational plist を扱い、write/reload は既存 gate と terminal human review が必要。
- `pushd transfer executor-run` / `diffd transfer executor-run` は dev-state fake-rclone 専用の queue executor tick。`--execute --consume-on-success` で fake transfer と successful record consume まで行う。manual-review record がある場合は fake-rclone 開始前に拒否する。
- `pushd launchd executor-plist` / `diffd launchd executor-plist` は dev-state fake-rclone queue executor 用の StartInterval LaunchAgent plist surface。`.dev-state/launchd/com.example.pcloud-*-executor.dev.plist` だけを書ける。public LaunchAgent write、`launchctl`、real transfer automation は行わない。
- `pushd transfer automation-gate` / `diffd transfer automation-gate` は public real-transfer queue executor automation の read-only gate。予定 public executor label/plist/StartInterval と automation command readiness を表示し、reviewer/operator approval が揃うまで public plist write、`launchctl`、automatic real transfer は行わない。
- `pushd transfer automation-run` / `diffd transfer automation-run` は gated automatic real-transfer executor tick。real-transfer gate、automation gate、automation-run gate、saved shadow validation report、non-`fake-rclone` rclone、`--execute`、`--consume-on-success`、manual-review 0 件が揃うまで拒否する。default は `--max-records 1` で one transfer record per tick だけ実行/consume し、失敗/不明/deferred record は保持する。automation launchd review は multi-record plan でも confirmed selected target 1 件を current bounded automation tick として approve できる。
- `pushd launchd automation-plist` / `diffd launchd automation-plist` と `automation-reload` は public real-transfer queue executor LaunchAgent write / reload gate。terminal-reviewed flags と service-specific plist/reload gate が揃うまで、public plist write、`launchctl`、automatic real transfer は行わない。operational public executor plist は `--max-records 1` を含む必要がある。
- 2026-05-07 時点で pushd public executor plist は bounded payload で write/reload 済み。observed launchd runs は queued screenshot uploads を 1 tick 1 record で upload/consume している。diffd polling plist も `StartInterval 60` で write/reload 済み。diffd public download executor automation は planned downloads 0 のためまだ未稼働。
- transfer plan は allowlist/default-exclude 判定後に hidden path component を excluded/skipped にする。macOS screenshot などの transient dotfile は automatic transfer command に出さない。
- `pushd queue prune-excluded` は excluded queue record だけを remove する cleanup surface。preview は read-only。dev `--execute` は dev-state guard、public `--execute` は `--reviewer-approved-excluded-record-cleanup` と `PCLOUD_TOOLS_PUSHD_QUEUE_PRUNE_EXCLUDED_GATE=operator-approved-pushd-queue-prune-excluded-v1` が必要。
- live automatic upload は bounded pushd executor tick だけ実行済み。diffd automatic download transfer、normal sync/resync、listing cache 操作、autosync launchd changes は pushd/diffd daemon path からはまだ実行しない。

preview plan:

- `pushd preview` reads `state_dir/pushd/queue.json`.
- `pushd status` and `diffd status` read `state_dir/{pushd,diffd}/last-transfer.json` when present and expose `last transfer status` plus success/failed/timeout counts. This is read-only status reporting and does not consume queue/change files.
- pushd queue item schema is a JSON list of strings or objects with at least `path`; optional `action` / `op` and `reason` are preserved in the preview records.
- pushd plan applies the configured allowlist and `PCLOUD_TOOLS_DEFAULT_EXCLUDES`, then reports planned uploads, excluded records, and invalid records.
- `diffd preview` reads `state_dir/diffd/remote-changes.json` and daemon pending downloads from `state_dir/daemon/pending-downloads.json`.
- diffd plan applies the configured allowlist and `PCLOUD_TOOLS_DEFAULT_EXCLUDES`, then reports remote changes, pending downloads, planned downloads, and skipped records.
- `pushd queue add|clear` and `diffd remote-change add|clear` are preview-first command surfaces for editing plan-state JSON manually.
- In dev mode, `--execute` writes only `state_dir/pushd/queue.json` or `state_dir/diffd/remote-changes.json`.
- Execute is refused unless `state_dir` is under `workspace/.dev-state/state`, even when `PCLOUD_TOOLS_DEV=1`.
- `pushd run` and `diffd run` are one-shot dry-run command surfaces.
- `run --execute` records only `last-plan.json`, `last-event.json`, and `cursor` under `state_dir/{pushd,diffd}/`; it does not mutate the queue/change files or perform transfer IO.
- `pushd gate` and `diffd gate` are read-only command surfaces that report any expansion beyond the currently approved queue-only fswatch resident and bounded API one-shot as closed, especially real upload/download execution.
- `pushd launchd status` and `diffd launchd status` are read-only launchctl print surfaces. They inspect `gui/<uid>/com.takafumi.pcloud-{pushd,diffd}` without changing launchd state.
- `pushd launchd review` / `diffd launchd review` show the public plist path, label, ProgramArguments, foreground preview command, and terminal review commands before public write or registration.
- `pushd launchd plist --public-write --execute` / `diffd launchd plist --public-write --execute` write the public LaunchAgent plist only after service-specific plist gate env and review flags are present. They do not run `launchctl`.
- `pushd launchd register --execute` / `diffd launchd register --execute` run only service-specific `launchctl enable` + `bootstrap` after the public plist exists, a saved ok shadow validation report is supplied, and all review flags plus `PCLOUD_TOOLS_{PUSHD,DIFFD}_LAUNCHD_GATE` are present.
- `pushd launchd resident-plist --execute` writes the operational fswatch resident plist only. The operational payload includes `pushd fswatch resident-run --operator-reviewed-probe --reviewer-approved-queue-policy --reviewer-approved-process-policy --execute --report-path <absolute report>` plus `PATH` and `PCLOUD_TOOLS_PUSHD_FSWATCH_RESIDENT_GATE`.
- `pushd launchd reload --execute` runs only `launchctl bootout` -> `bootstrap` after an operational resident plist is present and `PCLOUD_TOOLS_PUSHD_LAUNCHD_RELOAD_GATE` plus reload review flags are present.
- `diffd launchd resident-plist --execute` writes the operational live API one-shot plist only. The operational payload includes `diffd api-poll long-poll-run --operator-reviewed-preview --reviewer-approved-response-policy --reviewer-approved-credential-policy --reviewer-approved-process-policy --live-api --max-iterations 1 --execute --report-path <absolute report>` plus `PATH`, `PCLOUD_TOOLS_DIFFD_API_LONG_POLL_GATE`, and optional `StartInterval` from `--start-interval-seconds`.
- `pushd launchd executor-plist --execute` and `diffd launchd executor-plist --execute` write only dev-state queue executor plists under `.dev-state/launchd/`. The payload runs `<dev entrypoint> <service> transfer executor-run --execute --consume-on-success --json` on `StartInterval`, with `PCLOUD_TOOLS_DEV=1`, `.dev-state/state`, `.dev-state/logs`, `PCLOUD_TOOLS_TRANSFER_EXECUTION_GATE=dev-fake-rclone`, and `.dev-state/bin/fake-rclone`. This is not a public launchd or real-transfer automation gate.
- `diffd launchd reload --execute` runs only `launchctl bootout` -> `bootstrap` after an operational bounded long-poll plist is present and `PCLOUD_TOOLS_DIFFD_LAUNCHD_RELOAD_GATE` plus reload review flags are present.
- `pushd launchd automation-plist` / `diffd launchd automation-plist` preview the public real-transfer executor plist payload and can write it only when terminal review flags, saved shadow report, automation gate review, public wrapper check, service-specific plist gate env, and public non-dev runtime pass.
- `pushd launchd automation-reload` / `diffd launchd automation-reload` preview the public executor `launchctl bootout` -> `bootstrap` command set and can execute it only when an operational automation plist, launchctl, terminal review/rollback flags, and service-specific reload gate env pass.
- `pushd fswatch preview --fixture <path>` parses a fixture-backed fswatch event list without starting fswatch, then previews the resulting upload plan with the same allowlist/default-exclude classifier used by `pushd preview`.
- Supported fswatch fixture rows are tab-separated `path<TAB>flags`, path-only rows, JSON object lines with `path` and optional `flags` / `events`, or a JSON list containing those object/string forms.
- `pushd fswatch probe` checks fswatch command availability with local PATH lookup and reports the one-shot command argv; it does not run fswatch, start a resident daemon, or write pushd state.
- `diffd diff preview --fixture <path>` parses a fixture-backed pCloud diff response without calling the pCloud API, then previews the resulting download plan with the same remote-change classifier used by `diffd preview`.
- Supported diff fixture payloads are JSON objects with `diffid` and `entries` / `changes` / `diff` lists, or JSON lists containing object/string entries. Each object entry uses `path` and optional `event` / `type` / `action` / `diffid`.
- `diffd api-poll preview` reports the intended one-shot API poll request shape (`GET`, `/diff`, current `diffid`, and batch `limit`) without configuring credentials, opening network connections, calling pCloud, or writing diffd state.
- `diffd api-poll long-poll-run --live-api --max-iterations 1 --execute` is the bounded live API execution path. It requires saved shadow validation, operator/reviewer API flags, and `PCLOUD_TOOLS_DIFFD_API_LONG_POLL_GATE`. Successful runs update the numeric diffid, append allowlisted remote-change records, update `diffd/folder-cache.json`, and write `api-long-poll-last-run.json`. It does not run download transfer.
- `pushd transfer preview` and `diffd transfer preview` emit concise human summaries and detailed `--json` planned `rclone copyto` argv from the current upload/download plans. Delete/rename/move-style records and same-path pushd/diffd conflicts go to manual review and are excluded from planned transfer commands. They do not run rclone, upload, download, consume queues, mutate cursors, or write service state.
- `pushd transfer check` and `diffd transfer check` are read-only real-transfer gate checklists. Their human output is concise; `--json` retains the full AI/reviewer audit detail. They report saved shadow validation status when `--report-path` is provided, accept `--sample-path <relative allowlisted path>` for the displayed dev-state sample setup and warn when it would not become a planned transfer, require the saved report to include `temporary workspace guard`, `temporary state dir guard`, and `unsafe state dir guard`, verify the report's temp workspace/state-dir shape, expose the first planned transfer and preview command, emit a dev-state-only setup -> preview -> check -> cleanup review command sequence when the plan is empty, list pending operator/reviewer approvals, keep `real transfer gate status: closed`, and write no service state.
- `pushd transfer run --execute` and `diffd transfer run --execute` are implemented only for dev fake-rclone testing. They require `state_dir` under `workspace/.dev-state/state`, `PCLOUD_TOOLS_TRANSFER_EXECUTION_GATE=dev-fake-rclone`, and `PCLOUD_TOOLS_RCLONE_BIN` resolving to an executable named `fake-rclone` under `workspace/.dev-state/`.
- dev fake-rclone transfer runs use `PCLOUD_TOOLS_TRANSFER_EXEC_TIMEOUT_SECONDS`, start fake-rclone in its own process group, clean up that fake process group on timeout, write `state_dir/{pushd,diffd}/last-transfer.json` for successful and failed fake execution attempts, and do not consume queue/change files. Timeout is reported as `PCLOUD_TOOLS_TRANSFER_EXEC_TIMEOUT`. They still report the real transfer gate as closed and must not be used for live pCloud upload/download.
- `pushd transfer consume preview` and `diffd transfer consume preview` read latest dev-state `last-transfer.json` and current queue/change state, then show which successful fake-rclone results would remove matching queue/change records. They are read-only, write no state, and do not consume queue/change files.
- `pushd transfer consume run --execute` and `diffd transfer consume run --execute` are guarded dev-state consume paths. They require the same dev-state guard as other local state writes, remove only queue/change records matching successful fake-rclone results, and do not open real rclone/pCloud transfer.
- `pushd transfer executor-run` and `diffd transfer executor-run` combine dev fake-rclone transfer execution and optional consume into one queue executor tick. They remain dev-state only, require the fake-rclone execution gate for `--execute`, keep `real transfer automation gate status: closed`, refuse manual-review records before fake-rclone start, and never use real rclone/pCloud transfer.
- `pushd transfer automation-gate` and `diffd transfer automation-gate` are read-only public queue executor automation gates. They reuse the real-transfer final-review checklist, expose `PCLOUD_TOOLS_REAL_TRANSFER_AUTOMATION_GATE=operator-approved-real-transfer-automation-v1`, list the planned public executor service label/plist/StartInterval, and report `automation command status: implemented-gated` while keeping `public plist writes: no`, `launchctl execution: no`, and `automatic real transfer execution: no`.
- `pushd transfer real-gate|real-run` and `diffd transfer real-gate|real-run` support a manual selected-target path: when `--confirm-path` and `--confirm-direction` match exactly one planned transfer, the final review and guarded `real-run` can operate on only that selected command even if other planned records remain. With approved `--consume-policy remove-on-success-retain-on-failure`, successful selected records are consumed after exact successful transfer results while other planned records remain. This does not apply to public automation launchd review; multi-record automation remains a separate policy gate.
- `pushd transfer automation-run` and `diffd transfer automation-run` are guarded public executor ticks for automatic real transfer. ## 5. Sync モデル

### 5.1 基本方式

`sync` は `rclone bisync` を使って:

- Path1: `local:/Users/takafumi/p-core`
- Path2: `pcloud:core`

を同期します。

共通オプション:

- `--conflict-resolve newer`
- `--resilient`
- `--skip-links`

### 5.2 scope 制御

通常の `sync` / `autosync` は allowlist ベースです。

allowlist file:

- `/Users/takafumi/p-core/.pcloud-sync-allowlist`

filter output:

- `~/.pcloud/bisync.filter`

現在の live allowlist entries:

- `/`

重要:

- 実際の同期範囲は README の方針文よりも allowlist の内容が優先されます。
- 現在の live allowlist は p-core root scope です。
- `.pcloud-sync-allowlist` の `/` は p-core root scope を表します。`apps/`, `bin/`, `dev/`, `dotfiles/`, `project/`, `tools/` など source/tool roots も daemon 監視同期の対象になり、危険物・生成物・秘密情報は `.pcloudmanagerignore` と generated rclone filter で除外します。

### 5.3 mode

sync mode は内部的に次の種類です。

- `normal`
- `autosync`
- `resync`
- `full-resync`
- `track-renames`

意味:

- `normal`: allowlist 付き通常 bisync
- `autosync`: launchd watchdog から起動される allowlist 付き通常 bisync
- `resync`: allowlist 付きで bisync state を作り直す
- `full-resync`: allowlist を外した one-shot full-tree resync
- `track-renames`: rename tracking 付きの foreground sync

### 5.4 scope guard

allowlist scope と full-tree scope を行き来すると bisync state の前提が変わるため、`last-resync-scope` を `~/.pcloud/last-resync-scope` に記録します。

ルール:

- 通常 sync の前に前回の resync scope と今回の scope を比較する
- scope が変わっていたら通常 sync は拒否する
- 対応する `resync` が成功したときだけ baseline を更新する

## 8. 自動復旧と既知の障害対策

### 8.1 stale rclone lock

sync 開始前に `rclone` の `.lck` を読み、PID が死んでいれば stale/invalid lock として削除します。

手動操作:

- `pcloud-manager sync clear-stale-lock`

### 8.2 missing `.lst` / present `-err`

この環境では、bisync が `.lst` を失い `-err` だけ残す事象が繰り返し起きています。

現在の対策:

- sync 開始前に
  - `path1.lst` と `path2.lst` が両方 missing
  - `path1.lst-err` と `path2.lst-err` が両方 present
  のときだけ、保守的に `-err -> .lst` を自動復旧する

これは通常 sync / autosync の入口で実行されます。

### 8.3 `.DS_Store` と特殊ファイル

既定 exclude:

- `.DS_Store`
- `**/.DS_Store`
- `config/dotfiles/.ssh/agent/**`

これは、比較ノイズや transfer 不能な agent socket を減らすためです。

## 9. autosync と mount

### 9.1 autosync

autosync は `launchd` 管理です。

代表設定:

- label: `PCLOUD_MANAGER_AUTOSYNC_LABEL`
- plist: `PCLOUD_MANAGER_AUTOSYNC_PLIST`

公開操作:

- `sync enable-autosync`
- `sync disable-autosync`

設計意図:

- 手動 sync と autosync は同じ lock を共有して重複実行を避ける
- risky cleanup 中は autosync を止めてから触る

2026-04-27 に autosync は旧 document-only allowlist scope で復帰済みでした。現在の live allowlist は `/` で、daemon 監視同期を基本運用にします。`sync --execute` は daemon mode 中に拒否され、bisync は daemon を止めた maintenance 状態でのみ実行します。`last error` や launchd の `/tmp/pcloud-bisync.out` / `.err` には、復帰途中の rclone path 探索失敗など過去記録が残る場合があります。`sync status` / `status --detail` は latest result が success の場合に `last error status: historical` と表示し、latest result と併せて判断できるようにします。

### 9.2 mount

mount layer は optional です。

対象:

- `vault`
- `crypt`

方式:

- `rclone serve webdav`
- `rclone serve nfs`

からの local mount

`status` では disabled layer も表示されます。disabled の layer に対する mount/umount は拒否されます。

## 10. 既知の注意点

- `pCloud` roundtrip では `exec bit` を信頼しない
- `core` mount はまだない
- `doctor` は修復コマンドではなく bundle 出力のみ
- `ask` 連携は外部 wrapper に任せ、`pcloud-manager` は provider 差分を持たない
- `last error` は最新 result が success でも過去記録として残る場合がある
