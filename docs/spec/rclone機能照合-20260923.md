# rclone公式機能の照合（2026-09-23）

調査範囲: 今回のイベント同期・移動・削除・一括転送と、pcloud-archiveの暗号化コピー・検証。公式ドキュメントの関連箇所と導入済みrclone v1.75.1のhelpを確認した。全ドキュメント・全backendを網羅した調査ではない。本書は実装候補と制約の記録であり、本番反映済みを意味しない。bisyncは候補外。

| 要件 | 先に使うrclone機能 | ラッパーに残る補完・確認事項 |
| --- | --- | --- |
| 変更ファイルの一括転送 | copy、files-from0、no-traverse、transfers、checkers | 方向・対象選択、処理世代、部分成功の確認。APIアクセスは残る |
| フォルダ内の除外付き移動 | move/movetoのfilter/exclude、可能な場合のサーバー側移動 | 既存の除外規則との意味の一致、元・先パスのscope、改名と編集の別イベント管理 |
| 新旧・内容比較 | update、checksum、check、lsjson等 | 秒精度での同日時・不明状態の保留。updateの既定挙動をそのまま方針としない |
| 通常の検証 | checkと項目別レポート | ハッシュなし・照合失敗を一致扱いにしない。対象と世代を結果へ結び付ける |
| 暗号化先の検証 | cryptcheck、必要時のcheck --download | 暗号化下位remoteのchecksum対応を確認。独自の暗号検証を作らない |
| 再試行・並列化・進捗 | retries、low-level-retries、transfers、checkers、use-json-log、stats | 結果の日本語表示と世代管理。二重の並列制御・無条件再試行を増やさない |
| 上書き時のローカル退避 | backup-dir等の適合を先に確認 | staging中のローカル編集との衝突保護を保つ。pCloud削除用の独自退避は再導入しない |

## 組合せで注意する契約

[update](https://rclone.org/docs/#u-update)は宛先の新しいファイルをスキップするが、時刻が同じでもサイズが異なる場合は転送する。今回の「同日時で内容が違えば保留」と一致しないため、対象選択で補完する。

[files-from0を含むファイル一覧指定](https://rclone.org/filtering/#files-from-read-list-of-source-file-names)はinclude/exclude/filter系の指定を無視する。既存scopeとignoreで事前選別した一覧のみを渡す。元のignoreファイルを別オプションでも渡せば安全になる、とは考えない。

[move](https://rclone.org/commands/rclone_move/)はフィルタなしで条件が合えばディレクトリをサーバー側移動し、フィルタありでは選択ファイルごとの移動になる。ファイルごとでも可能ならサーバー側移動を使う。[moveto](https://rclone.org/commands/rclone_moveto/)のディレクトリ指定はこの動作に従う。

[copyのログ出力](https://rclone.org/commands/rclone_copy/#logger-flags)は実行中に記録され、最終成功を保証するレシートではない。再試行による重複や、no-traverseによる宛先のみの項目の省略を考慮する。終了結果と必要な検証を結び付け、成功を確認できた対象だけを処理済みにする。

[check](https://rclone.org/commands/rclone_check/)は非破壊のサイズ・ハッシュ比較を提供する。[crypt](https://rclone.org/crypt/#modification-times-and-hashes)では通常のchecksumが保持されず、公式は暗号化先の検証に[cryptcheck](https://rclone.org/commands/rclone_cryptcheck/)を案内している。cryptcheckは下位remoteのchecksum対応が必要で、nonceを読み、ローカル内容を暗号化してchecksumを比較する。暗号化ファイル全体の再ダウンロードを前提としないが、ローカル読み取り・暗号化計算とリモートアクセスは残る。

[JSONログ](https://rclone.org/docs/#use-json-log)は行ごとのJSONとして進捗・統計を取得できる。[並列転送](https://rclone.org/docs/#transfers-int)と再試行はrcloneの機能を先に使う。[backup-dir](https://rclone.org/docs/#backup-dir-string)は既存動作と退避先の制約を確認して適用を判断する。

## 現行コードとの対応

実装repo基準でsrc/pcloud_tools/pcloud_archive.pyの_copy_commandは既にcopy・transfers・checkers・retries等へ委譲している。一方、_check_commandは暗号化先にもcheck --one-wayを呼ぶため、cryptcheck等へ切り替える適合確認が必要。現時点では挙動を変更していない。

今回のイベント同期の実装前に、既存executorが自前で持つ転送並列化・リトライ・結果解析をこの表と照合し、rcloneに任せられる部分を減らす。世代確認・staging・未完了attemptの復旧は、同じ保証が確認できる形で接続する。


## 0.3.2の名前対応修正

転送のlocal encodingを通常設定 `Slash,InvalidUtf8,Dot` に固定する。pCloudの既定は `Slash,BackSlash,Del,Ctl,InvalidUtf8,Dot`。Standard/local境界を合成し、全角「／」を名前のまま保持する。公式の引用規則に対して往復できない表記や重複を拒否する。localの名前発見だけはRawでnative名を取得する。実rcloneの往復とpCloud相当encodingのfixtureに加え、対象12件のAPI実名・file ID・rclone出力と既存local10件の一致を読み取り確認した。独自decoderを根拠にユーザーへ改名を要求しない。

参照: [restricted filenames](https://rclone.org/overview/#restricted-filenames)、[pCloud encoding](https://rclone.org/pcloud/#encoding)、[pCloud filename restrictions](https://docs.pcloud.com/structures/filenames.html)、[rclone v1.75.1 encoder](https://github.com/rclone/rclone/blob/v1.75.1/lib/encoder/encoder.go)。
