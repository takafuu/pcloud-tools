# pcloud-manager 利用ガイド

Last updated: 2026-08-28

## release版をinstallする

`pcloud-tools`はGitHub Releasesだけで配布します。installerを確認してから実行する標準手順:

```sh
curl -LsSf https://raw.githubusercontent.com/takafuu/pcloud-tools/main/install.sh -o install.sh
less install.sh
sh install.sh
```

短縮形:

```sh
curl -LsSf https://raw.githubusercontent.com/takafuu/pcloud-tools/main/install.sh | sh
```

installer自体とpackage versionを固定する場合:

```sh
curl -LsSf https://raw.githubusercontent.com/takafuu/pcloud-tools/v0.1.0/install.sh -o install.sh
sh install.sh --version 0.1.0
```

既定ではuv tool environmentを`${XDG_DATA_HOME:-$HOME/.local/share}/pcloud-tools`、薄いwrapperを`$HOME/bin`へ配置します。このMacでは`$HOME/bin`が`/Users/takafumi/p-core/bin`を指します。release版は`/Users/takafumi/p-core/dev/pcloud-tools`やdevelopment `.venv`を参照しません。

installerはconfig、state、`rclone.conf`、pCloud credentials/remotes、launchd、NAS serviceを変更しません。install後に公開diagnosticsから設定を進めます。

```sh
pcloud-manager --version
pcloud-manager info
pcloud-manager info paths
pcloud-manager doctor
pcloud-archive help config
```

同じinstallerを再実行するとrelease runtimeを置換できます。config/state/logはruntime外なので保持されます。

## public 入口

通常利用はpublic wrapperを使います。wrapperはuvでinstallされたrelease executableへ委譲するだけで、development sourceをimportしません。

```sh
pcloud-manager
pcloud-manager --help
pcloud-manager help
pcloud-manager help --detail
pcloud-manager help --ai "pushd の launchd 状態を安全に見たい" --topic pushd --topic launchd
pcloud-manager status --json
pcloud-manager doctor --json
pcloud-manager pushd status --xbar
pcloud-manager diffd status --xbar
```

root help は public 名で表示されます。`pcloud-manager` は `usage: pcloud-manager ...`、`./pcloud-manager-dev` は `usage: pcloud-manager-dev ...` です。

`help --ai` は外部 AI/helper に渡すための JSON context generator です。LLM は呼ばず、生成 command も実行せず、state 書き込みや private/large content 読み込みもしません。代表 topic は `overview`, `safety`, `pushd`, `diffd`, `launchd`, `transfer`, `sync`, `config` です。

## public wrapper config

public `pcloud-manager` は `/Users/takafumi/.config/pcloud-tools/.env` を読みます。`/Users/takafumi/.config` は `/Users/takafumi/p-core/dotfiles/.config` への symlink なので、実体は dotfiles 配下です。

この live `.env` は machine-local config として扱い、tools repo では追跡しません。共有できる非 secret key の一覧は `/Users/takafumi/p-core/dev/pcloud-tools/.env.example` を参照します。

```sh
pcloud-manager doctor --repair --json
pcloud-manager status --json
pcloud-manager doctor --json
```

`doctor --repair` は missing `.env` の starter config を作ります。これは設定ファイル作成だけで、launchd 作成/変更/load、fswatch 常駐、pCloud API long-poll、実 upload/download は行いません。

`sync scope` は `.pcloud-sync-allowlist` を読み、`/` を p-core root scope として扱います。`status` / `doctor` / `sync status` / `sync scope` は sync scope file と `.pcloudmanagerignore` の診断を返しますが、live sync scope は自動変更しません。

daemon監視同期とbisync preview/maintenanceは同じ`.pcloud-sync-allowlist`を読みます。危険物・生成物・秘密情報は`.pcloudmanagerignore`とgenerated rclone filterで除外します。bisyncを使う場合はmode switchでdaemonを止めたmaintenance状態にします。

## pushd / diffd daemon surfaces

`pcloud-pushd` / `pcloud-diffd` はpublic wrapperから利用できます。どちらもpreview-first / human-gatedです。

基本動作:

- `pcloud-pushd`: sync scope内のlocal eventをupload queueへ追加します。
- `pcloud-diffd`: pCloud `/diff` APIのremote changeをdownload queueへ追加します。
- `pushd transfer executor-run` / `diffd transfer executor-run` は dev-state fake-rclone 専用の queue executor tick です。`pushd launchd executor-plist` / `diffd launchd executor-plist` はこの dev executor tick 用の `.dev-state/launchd` plist だけを書けます。`pushd transfer automation-gate` / `diffd transfer automation-gate` は public real-transfer automation の read-only gate で、pushd 側は bounded upload tick だけ live、diffd download transfer、normal sync/resync、listing cache 操作はまだ閉じています。
- `pushd transfer real-gate` / `diffd transfer real-gate` と `real-run` は、terminal で確認した `--confirm-path` + `--confirm-direction` が planned transfer の exactly 1 件に一致した場合、その selected transfer だけを manual first-run 対象にできます。`--consume-policy remove-on-success-retain-on-failure` の承認下では、成功した matching record だけを消費し、他の planned record は触りません。
- `pushd transfer automation-run` / `diffd transfer automation-run` は gated automatic real-transfer executor tick です。real-transfer gate、automation gate、automation-run gate、saved shadow validation report、non-`fake-rclone` rclone、`--execute`、`--consume-on-success` が揃うまで state write、queue/change consume、real transfer は行いません。manual-review record は除外・保持されますが、他のeligible transferは継続し、manual-reviewだけを理由に周期jobがerror終了することはありません。pushd は gate が揃った tick 冒頭で missing-local upload cleanup を行ってから plan を組みます。default は `--max-records 1` で、1 tick 1 recordだけ実行します。
- queue が空の場合、public automation launchd review は直近の successful manual `real-run` を validation evidence として使えます。last transfer が service/direction に一致し、successful result があり、failed/timeout がない場合だけです。
- `pushd launchd automation-plist` / `diffd launchd automation-plist` と `automation-reload` は、public real-transfer executor LaunchAgent write / reload gate です。terminal review flags と service-specific plist/reload gate が揃うまで public plist write、`launchctl`、automatic real transfer には進みません。
- public executor payloadは`--max-records 1`を含むbounded tickとし、serviceの現在状態は各`status --json`と`launchd status --json`で確認します。
- hidden path component は transfer plan で excluded/skipped になります。`pushd queue prune-excluded` は excluded queue record だけを preview/cleanup するための surface で、public `--execute` には `--reviewer-approved-excluded-record-cleanup` と `PCLOUD_TOOLS_PUSHD_QUEUE_PRUNE_EXCLUDED_GATE=operator-approved-pushd-queue-prune-excluded-v1` が必要です。

```sh
pcloud-manager pushd status --xbar
pcloud-manager pushd preview --json
pcloud-manager pushd launchd status --json
pcloud-manager diffd status --xbar
pcloud-manager diffd preview --json
pcloud-manager diffd launchd status --json
```

live state:

- `pushd`: `/Users/takafumi/.pcloud/pushd/queue.json`
- `diffd`: `/Users/takafumi/.pcloud/diffd/remote-changes.json`
- diff cursor: `/Users/takafumi/.pcloud/diffd/cursor`
- diffd last API poll: `/Users/takafumi/.pcloud/diffd/api-long-poll-last-run.json`
- launchd logs: `/Users/takafumi/.pcloud/logs/pushd-launchd.out`, `/Users/takafumi/.pcloud/logs/diffd-launchd.out`

`pushd preview` は sync scope と default excludes を適用し、planned uploads / excluded queue items / invalid queue items を表示します。`diffd preview` は remote changes と pending downloads から planned downloads を表示します。

開発用 state を触る場合は `pcloud-manager-dev` を使います。`--execute` は dev mode の state JSON だけを書き換え、`PCLOUD_TOOLS_STATE_DIR` が workspace の `.dev-state/state` 配下から外れている場合は拒否されます。

```sh
./pcloud-manager-dev pushd queue add dev-fixtures/Documents/example.pdf
./pcloud-manager-dev pushd queue add dev-fixtures/Documents/example.pdf --execute
./pcloud-manager-dev pushd queue clear
./pcloud-manager-dev pushd queue clear --execute
./pcloud-manager-dev diffd remote-change add dev-fixtures/Documents/example.pdf
./pcloud-manager-dev diffd remote-change add dev-fixtures/Documents/example.pdf --execute
./pcloud-manager-dev diffd remote-change clear
./pcloud-manager-dev diffd remote-change clear --execute
```

dry-run 結果だけを記録する場合:

```sh
./pcloud-manager-dev pushd run
./pcloud-manager-dev pushd run --execute
./pcloud-manager-dev diffd run
./pcloud-manager-dev diffd run --execute
```

`run --execute` は `last-plan.json` / `last-event.json` / `cursor` だけを dev state 配下に記録します。

### launchd 操作の確認

通常確認:

```sh
pcloud-manager pushd launchd status
pcloud-manager diffd launchd status
pcloud-manager pushd status --xbar
pcloud-manager diffd status --xbar
```

human-gated gate:

```sh
pcloud-manager pushd launchd review
pcloud-manager pushd launchd resident-plist --report-path /Users/takafumi/p-core/dev/pcloud-tools/.dev-state/reports/shadow-validation.json
pcloud-manager pushd launchd reload --report-path /Users/takafumi/p-core/dev/pcloud-tools/.dev-state/reports/shadow-validation.json
pcloud-manager diffd launchd review
pcloud-manager diffd launchd resident-plist --report-path /Users/takafumi/p-core/dev/pcloud-tools/.dev-state/reports/shadow-validation.json --start-interval-seconds 60
pcloud-manager diffd launchd reload --report-path /Users/takafumi/p-core/dev/pcloud-tools/.dev-state/reports/shadow-validation.json
```

`resident-plist --execute` は public plist write だけ、`reload --execute` は service-specific `bootout -> bootstrap` だけです。どちらも reviewer/operator flags と gate env が必要です。`reload` は実際に daemon/one-shot を起動するため、terminal review 後の明示承認なしに実行しません。

dev-state queue executor の確認:

```sh
./pcloud-manager-dev pushd transfer executor-run
./pcloud-manager-dev pushd transfer executor-run --execute --consume-on-success
./pcloud-manager-dev pushd transfer automation-gate
./pcloud-manager-dev pushd transfer automation-run --execute --consume-on-success
./pcloud-manager-dev pushd launchd executor-plist
./pcloud-manager-dev pushd launchd executor-plist --execute
./pcloud-manager-dev pushd launchd automation-plist
./pcloud-manager-dev pushd launchd automation-reload
./pcloud-manager-dev pushd queue prune-excluded
./pcloud-manager-dev pushd queue prune-excluded --execute
./pcloud-manager-dev diffd transfer executor-run
./pcloud-manager-dev diffd transfer executor-run --execute --consume-on-success
./pcloud-manager-dev diffd transfer automation-gate
./pcloud-manager-dev diffd transfer automation-run --execute --consume-on-success
./pcloud-manager-dev diffd launchd executor-plist --start-interval-seconds 60
./pcloud-manager-dev diffd launchd executor-plist --start-interval-seconds 60 --execute
./pcloud-manager-dev diffd launchd automation-plist --start-interval-seconds 60
./pcloud-manager-dev diffd launchd automation-reload --start-interval-seconds 60
```

`executor-run --execute` は fake-rclone gate と `.dev-state/state` guard が必要です。pushd executor は queue を「変更された可能性がある path」として扱います。録音・コピー中の file は size / mtime fingerprint が変わるたびに待機時間をリセットし、同じ状態が `PCLOUD_TOOLS_PUSHD_UPLOAD_SETTLE_SECONDS` 続いてから upload します。コピー後 rename の消えた旧名や `*.tmp.<pid>.<random>` など、executor tick 時点で存在しない `upload` 候補は、過去のupload成功履歴に関係なくそのtickで通知なしに自動cleanupされます。以前uploadしたpathに対する明示的な`delete` / `rename` eventだけmanual reviewに残り、xbarの確認行を選ぶと対象のtransfer previewがTerminalで開きます。rclone が転送中の更新を検出してもエラー通知せず、次 tick の settling に戻ります。

`executor-plist --execute` は `.dev-state/bin/fake-rclone` がある dev mode でだけ `.dev-state/launchd/com.example.pcloud-*-executor.dev.plist` を書きます。public LaunchAgent、`launchctl`、real transfer automation には進みません。

`automation-gate` は read-only で、予定する public executor label/plist/StartInterval と automation command readiness を表示します。`automation command status: implemented-gated` でも、このコマンド自体は public plist write / `launchctl` / automatic real transfer を実行しません。

`automation-run` は public executor tick 本体です。`PCLOUD_TOOLS_REAL_TRANSFER_EXECUTION_GATE=operator-approved-real-transfer-v1`、`PCLOUD_TOOLS_REAL_TRANSFER_AUTOMATION_GATE=operator-approved-real-transfer-automation-v1`、`PCLOUD_TOOLS_REAL_TRANSFER_AUTOMATION_RUN_GATE=operator-approved-real-transfer-automation-run-v1`、saved ok shadow validation report、`--execute`、`--consume-on-success`、non-`fake-rclone` rcloneが揃うまで拒否します。manual-review recordはstatus/xbarで確認待ちとして保持し、転送対象からは除外します。これらはeligible transferを止めず、反復chat通知もしません。pushdはgateが揃った実行tickだけmissing-local startup cleanupを行います。defaultは`--max-records 1`で、成功したexecuted recordだけconsumeし、失敗/不明/deferred recordは保持します。public automation launchd reviewはconfirmed selected targetをcurrent bounded tickとして扱えます。

`automation-plist` / `automation-reload` は public 実行系の直前 gate です。`automation-plist --execute` は terminal review flags、saved shadow report、automation gate review、public wrapper、service-specific plist gate env、public non-dev runtime が揃った場合だけ public executor plist を書きます。`automation-reload --execute` は operational automation plist、launchctl、terminal review/rollback flags、service-specific reload gate env が揃った場合だけ `bootout -> bootstrap` を実行します。どちらも terminal human approval なしに進めません。

public executor payloadを変更した場合、`--max-records 1`を含まないplistは`operational automation plist: pending`として扱います。

shadow validation の準備確認:

```sh
python3 scripts/pcloud-shadow-validation.py
python3 scripts/pcloud-shadow-validation.py --json
mkdir -p .dev-state/reports
python3 scripts/pcloud-shadow-validation.py --report-path .dev-state/reports/shadow-validation.json
```

このスクリプトは一時 workspace の `.dev-state/` だけを使い、preview / dry-run / action / safety guard を確認します。

operator checklist:

- `python3 scripts/pcloud-shadow-validation.py --report-path .dev-state/reports/shadow-validation.json` が exit code 0 で終わる
- 保存した JSON の `schema_version` が `pcloud-tools-shadow-validation.v1`
- top-level `status` が `ok`
- `checks[]` の全 item が `status: ok`
- `pushd dry-run state`、`diffd dry-run state`、`unsafe state dir guard` が含まれる
- `temporary workspace guard` と `temporary state dir guard` が含まれ、どちらも `status: ok`
- `workspace` が system temporary directory 直下の `pcloud-shadow-validation-* / workspace`
- `state_dir` が `workspace/.dev-state/state` と完全一致する
- `~/.pcloud`、`/Users/takafumi/.pcloud`、`pcloud:core`、実 upload/download、live `launchctl`、live fswatch 常駐を示す結果がない

追加変更前 gate:

- 上の checklist が 1 つでも失敗したら、新しい public launchd 変更や transfer gate 実行に進まない
- `pushd` / `diffd` の real upload/download は有効化しない
- normal sync/resync、listing cache 操作、autosync launchd changes はこの daemon 検証とは別 gate にする
- old monolith は `legacy old-monolith-*` 以外では archive しない

rollback 判断:

- validation report が `status: error`、または任意の check が `error` の場合は rollback 判断とする
- rollback 時は public `pcloud-manager` wrapper を現行実装のまま維持し、今回の Python dev surface は preview/dry-run の修正対象として扱う
- `--report-path` で保存した JSON を reviewer への報告に添え、失敗した check name と detail を起点に修正する

## pcloud-archive

設定したローカルフォルダから `pcloud-crypt:` へ一方向の差分コピーを行う場合は、`pcloud-manager` ではなく `pcloud-archive` を使います。crypt mountは不要です。初回は `~/.config/pcloud-archive/config.toml` に実在する `source_root` とcrypt内の `remote_root` を設定します。

```sh
pcloud-archive doctor
pcloud-archive diff
pcloud-archive promote <path> --dry-run
pcloud-archive promote <path> --execute
pcloud-archive check <path> --execute
```

`pcloud-archive` は `rclone copy` / `rclone check` でremoteへ直接接続します。ローカル削除はpCloudへ自動反映しません。使い方と説明書の場所は `pcloud-archive help --detail` または `pcloud-archive info paths` で再発見できます。詳細は `/Users/takafumi/p-core/dev/#仕様書/pcloud-archive/` を参照してください。

短い概要は `man pcloud-archive` でも確認できます。man pageは任意の説明入口であり、未設置でも `doctor` のwarning/errorにはしません。
