## 現行契約

- public surfaceはpcloud-manager / pcloud-tools / pcloud-pushd / pcloud-diffd / pcloud-archive。help / help --ai / info / info paths / doctorの既存契約を維持する。
- 開発checkoutとinstall済みの非editable wheelを分離する。本番wrapper/LaunchAgentはdevelopment src、venv、reportへの実行時依存を持たない。互換入口もpublic wrapperへ委譲する。
- 開発CLIは `pcloud-manager-dev`。config/state/log/rclone config/cacheを `.dev-state` 内で使う。fixture中心の検証を既定とし、本番credentialや本番queueを開発へコピーしない。archiveのテストも一時config/source/remoteを使う。
- 本番config/state/logはruntime外に保持する。検証レポートは `~/.pcloud/validation/` のハッシュ付き実ファイルとして採用し、移設時のbytes一致とinstall済み版での受理を確認する。
- source変更は本番へ自動反映しない。検証済みreleaseを明示的にinstallする。installerはcredential/config/state/launchdを変更しない。
- service設定の移行は元ファイル・modeをbackupしてから行う。queue/journalへ書く全writer（resident watcher、API poller、executor、manual、backfill）を停止し、開始済みchildの終了または回収を確認してから切替・切り戻しを行い、loaded program/argumentsを確認する。未登録のまま放置せず、復旧または切り戻しを行う。通常の性能設定の回復はconcurrency=1を次tickから反映する操作として分けて扱う。
- 今回の高速化変更ではqueueの既存string/object読取、同期scope、転送gate、暗号化方式を維持し、event_id・attempt journal・performance計測を追加フィールドとして扱う。event_idのない旧recordは実行可能なtickでlock下に補完し、選択世代の一致を確認してconsumeする。pushd/diffdの同時転送数は環境設定の1〜4（既定1）で、開発検証はfake-rclone・一時workspace・一時stateだけを使う。
- 未確定attemptが残る間はexecutorの再起動・child start・consumeを拒否する。明示的な復旧後は元attemptのevent_idと転送前fingerprintを再評価し、変更済みlocalを上書きせずconflict/manual-reviewとして保持する。

## 実装と検証

入口は `pcloud-manager-dev` と `install.sh`、設定は `src/pcloud_tools/config.py` / `runtime.py`、認証の読み取りは `rclone_config.py`。回帰検証は既存テストに加え、bounded concurrency、event_id世代consume、常駐writerのlifetime sessionとcutover、timeout/process-group cleanup、attempt recovery、performance reportをfixtureで確認する。復旧の4確認flagは `--child-exit-confirmed`、`--writers-stopped`、`--latest-event-ids-rechecked`、`--local-fingerprints-rechecked` とし、実機の運用記録は本番state内へ置き、公開仕様へprivateなqueue内容やcredentialを記載しない。

仕様の正本はこの外部directory。repoの `docs/spec/` は `.source` の示す正本からコピーしたsnapshotで、commit/push前に更新する。ローカル変更や試験結果をrelease済みと表現しない。

## 古いdownload依頼と表示の検証契約

転送元不在の同一event除外、旧review marker清掃、別event・local・cursorの保持、認証/通信/child終了不明の保持、preview/gate未充足での不変性をfixtureで検証する。file IDの名前変更は最新diffidへ集約し、古い応答や無関係なfile ID・未知fieldを保持する。metadata未取得の旧recordを推測で削除しない。statusは実行中のtickと停止後に残る未確定attemptを区別する。

planのjournal/ignore読取はplan単位で共有し次planで再取得する。executorはwriter lifetime前にattemptを作らない。本番反映は従来どおりrelease wheel・全writer停止・child終了確認・backup・report受理・4サービス復帰で行い、設定scopeやgateを変更しない。

pcloud-statusは別root `/Users/takafumi/p-core/dev/xbar/pcloud-status/`。要操作の分類と表示をfixtureで検証後に配備し、xbar symlinkを維持する。本体のinstalled packageをUI修正目的で直接編集しない。

切替時のexecutor停止では、実行中batchを途中でbootoutしない。install済みruntimeのtransfer_tick_lockを取得してbatch終了を待ち、その間に該当executorをbootoutする。全writer停止後はこのtick lockを解放し、writer_cutover_sessionでchild・未確定attempt・writer不在を確認して切り替える。tick lockを保持したままcutoverへ入ると自己保有のstate lockも停止条件に抵触するため、停止済みschedulerとcutover barrierで順序を明確にする。
