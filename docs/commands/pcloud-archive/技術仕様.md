# pcloud-archive 技術仕様

Last updated: 2026-08-28

## 目的と境界

`pcloud-archive` は、設定されたローカル `source_root` から `pcloud-crypt:` 内の `remote_root` へ、rcloneで直接ファイルを一方向コピーして検証する手動CLIです。双方向sync、削除伝播、crypt mount管理は担当しません。

```text
local source_root -> rclone copy/check -> pcloud-crypt:remote_root
```

`pcloud-manager mount crypt` が作るFinder用mountは任意です。`pcloud-archive` はmount状態に依存しません。

## エントリポイントと管理場所

- distribution: `pcloud-tools`
- public wrapper: `/Users/takafumi/p-core/bin/pcloud-archive`
- installed executable: `${XDG_DATA_HOME:-$HOME/.local/share}/pcloud-tools/bin/pcloud-archive`
- development implementation: `/Users/takafumi/p-core/dev/pcloud-tools/src/pcloud_tools/pcloud_archive.py`
- tests: `/Users/takafumi/p-core/dev/pcloud-tools/tests/test_pcloud_archive.py`
- package script: `pcloud-archive = "pcloud_tools.pcloud_archive:main"`
- canonical work / git root: `/Users/takafumi/p-core/dev/pcloud-tools`
- canonical docs: `/Users/takafumi/p-core/dev/#仕様書/pcloud-archive/`
- man page source: `/Users/takafumi/p-core/dev/pcloud-tools/docs/man/pcloud-archive.1`
- installed man page: `/opt/homebrew/share/man/man1/pcloud-archive.1` -> sourceへのsymlink
- git policy: `pcloud-tools` repo内のsibling CLIとして管理し、別repoは作らない。

正式版はGitHub Releaseの`pcloud-tools` wheelからuv tool environmentへinstallする。public wrapperはinstalled executableへの委譲だけを行い、development rootやdevelopment `.venv`を参照しない。config/state/rclone credentialsはpackage外に残す。

## help / info / doctor設計

`help` は内部用語の `staging` / `promote` / `canonical` を前提にせず、コピー元、コピー先、mount不要、一方向copy、削除非伝播、初回設定、標準手順を明示する。

`help --detail` は解決した説明書ディレクトリと3文書の存在状態を表示し、`cd`、`ls -1`、`open 利用ガイド.md` を案内する。説明書が見つからなくてもCLI本体は停止しない。

同時にman pageのsource、installed path、status、`man pcloud-archive` を表示する。man pageは任意の再発見入口であり、未採用・未設置時は `not used` とする。

`info paths` はpublic command、implementation、config、source root、remote root、state/log、manifest/tombstone/last-run、man page source/installed path、説明書ディレクトリと説明書ファイルを表示する。

`doctor` はsource root、rclone、`pcloud-crypt:` base remote到達性を診断する。crypt mountとman pageは必須条件にしない。未設定のsource rootを架空のNASパスへ置換せず、`source root is not configured` としてerrorにする。man pageがなければissueを追加せず `man page status: not used`、`man page required: no` と情報表示し、doctor status/exit codeへ影響させない。

config fileがない場合、`doctor` と `info` は `pcloud-archive help config` と `pcloud-archive help config --init-config <config_path>` への短い誘導を共通表示する。TOML全文は通常の診断出力へ載せず、`help config` に集約する。

## man page

man pageはCLIの用途、初回設定、標準workflow、config、files、安全性、完全な説明書への導線を載せる短いoperator向け概要です。完全な仕様の正本はMarkdown文書です。

sourceをrepo内 `docs/man/pcloud-archive.1` に置き、既存manpathの `/opt/homebrew/share/man/man1/pcloud-archive.1` からabsolute symlinkで参照します。`mandb` は要求しません。

```sh
mandoc -T lint /Users/takafumi/p-core/dev/pcloud-tools/docs/man/pcloud-archive.1
man -w pcloud-archive
MANPAGER=cat man pcloud-archive
```

## 設定

Config resolution:

1. CLI flags
2. `PCLOUD_ARCHIVE_*` environment variables
3. `~/.config/pcloud-archive/config.toml`
4. safe built-in defaults

`source_root` は必須で、組み込みパスを持たない。`remote_root` の安全な未設定時fallbackは `pcloud-crypt:_pcloud-archive-dev`。rclone credentialsはrclone configが所有し、pcloud-archive configへsecretを保存しない。

`help config --init-config <config_path>` はparent directoryを作り、starter TOMLを新規作成する。既存ファイルは上書きしない。starterの `source_root` は空文字列、`remote_root` は安全なdev fallbackとし、作成後もsource未設定として診断される。`help --ai` との併用はread-only契約維持のため拒否する。

```toml
[defaults]
profile = "mac"

[profiles.mac]
source_root = "/absolute/path/to/local/archive-source"
remote_root = "pcloud-crypt:archive"
state_dir = "~/.local/state/pcloud-archive/mac"
log_dir = "~/.local/state/pcloud-archive/logs"
rclone_bin = "rclone"

[profiles.mac.transfer]
transfers = 3
checkers = 8
bwlimit = "8M"
tpslimit = 4
retries = 5
low_level_retries = 10

[profiles.mac.ignore]
patterns = [".DS_Store", "**/.DS_Store", "@eaDir/**", "**/@eaDir/**", "*.tmp", "*.part"]
```

## 説明書探索

説明書directoryの解決順は次のとおりです。

1. `PCLOUD_ARCHIVE_DOCS_DIR`
2. 選択profileの `docs_dir`
3. 解決済みpublic commandと実装ファイルの各親directoryから `<root>/dev/#仕様書/pcloud-archive/` と `<root>/#仕様書/pcloud-archive/` を探索
4. installed wheel内の`pcloud_tools/share/docs/pcloud-archive/`

説明書はsoft dependencyです。未検出時は `help --detail` / `info paths` / `doctor` に表示するが、rclone処理の可否には影響させない。

## 状態と転送モデル

- manifest: `<state_dir>/manifest.json`
- tombstones: `<state_dir>/tombstones.json`
- last run: `<state_dir>/last-run.json`
- `diff`: local/remote inventoryを比較し、`source only` / `same` / `different` / `remote only` / `tombstoned-local` で表示する。stateは書かない。
- `promote`: `rclone copy`。既存remote-only fileを削除しない。
- `check`: `rclone check --one-way`。成功時にmanifestとlast-runを書く。
- `delete-canonical`: `rclone deletefile`。成功時にtombstoneとlast-runを書く。
- `drop-cache`: 現在preview-only。

## 現在の制限

- `diff` のsame/different判定はsizeベース。
- launchd化は未実装。
- `delete-canonical` は単一file path前提。
- `drop-cache` はpreview-only。
